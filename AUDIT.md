# Аудит интернет-магазина «Хвиля»

Дата: 11.10.2026 · SvelteKit 3.0.1 + Svelte 5.57 · `adapter-static`, все страницы пререндерены. Проверялась production-сборка через `vite preview`, сборка под GitHub Pages — отдельно на сервере, который ведёт себя как Pages (базовый путь `/hvylia`, `404.html` с кодом 404).

Инструменты:

- Lighthouse 12 — мобильный режим (Moto G Power, медленный 4G, 4× CPU) и десктоп;
- axe-core 4 через `@axe-core/playwright` (wcag2a/aa, wcag21aa, wcag22aa, best-practice);
- Playwright, curl;
- svelte-check, ESLint, Prettier.

## 3. Результаты по пунктам ТЗ

1. **Сборка и типы.** `vite build` без ошибок. `svelte-check --fail-on-warnings` — 0 ошибок, 0 предупреждений. ESLint и Prettier — чисто. 72 HTML-страницы + JSON-эндпоинты.
   - JS на старте (gzip): рантайм Svelte + иконки ≈ 31 КБ, общий код ≈ 56 КБ, страница 2–10 КБ.
   - Весь CSS встроен в HTML.
   - HTML страницы товара — 145 КБ (23 КБ gzip).
2. **SSR.** Все публичные страницы пререндерены: товары, тексты, мета, canonical и JSON-LD есть в HTML без JS.
   - Неизвестный адрес → 404 (и в `vite preview`, и на Pages).
   - Ошибок гидратации и сообщений в консоли нет (проверено Playwright на всех сценариях).
3. **Lighthouse** — см. раздел 1.
4. **SEO** (проверены все 71 индексируемая страница):
   - уникальные title (≤ 70) и description (50–170);
   - canonical без query у всех страниц;
   - один h1, иерархия заголовков без пропусков, `alt` у всех изображений;
   - `noindex` у кошика, checkout, порівняння, обраного, пошуку и страниц с фильтрами (выставляется при наличии query, canonical указывает на основной раздел);
   - `sitemap.xml` — 66 URL (категории, подкатегории, 7 SEO-страниц, 20 товаров, 9 брендов, инфо-страницы), `robots.txt`.

   JSON-LD:
   - `Organization`/`OnlineStore` с политикой возврата;
   - `WebSite` + `SearchAction`;
   - `BreadcrumbList` (65 страниц);
   - `CollectionPage` + `ItemList` (38);
   - `Product` + `Offer` (UAH, наличие, доставка, возврат) + `AggregateRating` + `Review` (20);
   - `FAQPage` (30), `Brand` (9).

   Рейтинги считаются из реальных отзывов в данных — цифры в JSON-LD совпадают с видимыми на странице.

5. **Фейковый API:**
   - фильтры с фасетами-счётчиками (каждый считается без учёта собственного фильтра), 5 сортировок;
   - пагинация реальными ссылками `?page=N` + «Показати ще»;
   - поиск с подсветкой;
   - города и отделения НП, создание заказа с валидацией (422 + ошибки полей);
   - задержка 200–600 мс → скелетоны со «волновым» шиммером.

   Несуществующий товар или категория → 404.

6. **Каталог и мега-меню.**
   - Мега-меню открывается кликом и наведением (задержки 180 / 260 мс), категория меняется при наведении. Esc закрывает его и возвращает фокус, клик снаружи — закрывает.
   - Мобильное меню: проваливание в категорию и «назад».
7. **Фильтры:**
   - синхронизация с URL, «назад/вперёд», комбинации (бренд + ANC);
   - прямые ссылки с фильтрами, чипы с удалением, «Скинути все»;
   - пустое состояние;
   - на мобильном — выезжающая панель.
8. **Товар:**
   - галерея с миниатюрами, лупой при наведении и полноэкранным режимом (стрелки, свайп, Esc);
   - выбор цвета, степпер, «Купити в 1 клік» (демо);
   - табы со стрелками и roving tabindex, отзывы с фильтром по оценке и демо-формой, вопросы;
   - «З цим купують», похожие, недавно просмотренные;
   - липкая панель покупки.
9. **Корзина, избранное, сравнение:**
   - всё сохраняется после перезагрузки, без `localStorage` работает в памяти;
   - промокод HVYLIA10, удаление с «Скасувати»;
   - checkout: валидация с фокусом на первом ошибочном поле, маска `+380 (67) 123-45-67`, поиск города и отделения;
   - страница заказа с номером и плашкой «Це демо-замовлення», корзина очищается.

   **Итого: 37/37 интерактивных проверок Playwright.**

10. **Качество UI.**
    - На 8 ключевых страницах у всех кликабельных элементов `cursor: pointer`, у disabled — `not-allowed`.
    - Видимых нативных `select`/`checkbox`/`radio`/`range`/`number` — 0: select — свой listbox, слайдер — 2 ручки + поля, количество — степпер, чекбоксы и радио — свои индикаторы поверх скрытых input.
    - Скроллбар стилизован глобально: `scrollbar-width`/`scrollbar-color` и `::-webkit-scrollbar` с hover. Это работает и во всех прокручиваемых блоках: мега-меню, фильтры, корзина, модалки, автокомплит.
    - Свой `::selection`, плавный скролл.
    - `scrollbar-gutter: stable` — модалки не сдвигают страницу, прокрутка фона блокируется.
11. **Доступность.** axe: **29/29 проверок без нарушений** — 11 страниц на 1440 и 390 px, плюс мега-меню, мобильное меню, панель фильтров, мини-корзина.
    - Модалки и drawer: фокус-ловушка, Esc, возврат фокуса, `inert` для фона.
    - Skip-link «Перейти до вмісту», aria-live для корзины и результатов фильтрации.
    - `role="slider"` с клавиатурой у цены, `role="combobox"`/`listbox` у поиска и селектов.
12. **Адаптив.** 360 / 768 / 1024 / 1440 — горизонтального скролла и выхода элементов за край нет.
13. **Код.**
    - Svelte 5: только руны, классы с `$state` в `.svelte.ts`, `$derived.by`, snippets, `class={[...]}`.
    - Код с `window`/`localStorage` выполняется только в браузере (`onMount`, `browser` из `$app/env` — в SvelteKit 3 он переименован из `$app/environment`).
    - Нет `any`, `console.*`, неиспользуемого кода. Отключения линтера только точечные, с пояснением (`{@html}` для JSON-LD, ссылки, уже прошедшие через `resolve()`).
14. **Уникальность** — см. раздел 4.

## 5. Отклонения от ТЗ и рекомендации

- **Без сервера (по решению заказчика).**
  - «API» — статические JSON, пререндеренные из `+server.ts`, плюс мок-клиент в браузере. Фильтрация, поиск, создание заказа и 422-ошибки работают там.
  - Отдельных `/api/search` и `/api/orders` как HTTP-эндпоинтов нет: на статическом хостинге они невозможны.
  - Страница заказа — `/order?id=…` вместо `/order/[id]`.
  - 301-редиректы на GitHub Pages недоступны.
- **Каталог:** 20 товаров по 3 фото (по решению заказчика). Подкатегория «Чохли» убрана — на неё не хватило товаров.
- **noindex для фильтров:** в статическом HTML всех вариантов адреса стоит одинаковый canonical на основной раздел, а `noindex` добавляется уже в браузере. Для полного серверного `noindex` нужен хостинг с SSR (Vercel/Netlify, `adapter-node`).
- **Мобильный Lighthouse в симуляции** 93–95. Что ещё можно сделать:
  - вынести мини-корзину и мобильное меню в динамический импорт (минус ~10 КБ на старте);
  - отдавать фото с CDN по ширине экрана.
- **Фото** — Unsplash (авторы в `CREDITS.json`); для реального магазина нужны собственные предметные съёмки на едином фоне. Бренды, отзывы и рейтинги вымышлены: для продакшена в JSON-LD должны быть реальные отзывы.
- **Реальный магазин:** API Новой Почты, платёжный провайдер, серверная обработка заказов и писем; домен вместо заглушки `hvylia.com.ua`.
